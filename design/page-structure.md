# general UX r2：完整页面与作品安排

日期：2026-11-02。输入为[完整内容r3](../content/README.md)，原版依据为[UI/UX基线](../baseline/ui-ux.md)。本表规定阅读顺序、主展示与补充查阅，不改写正文事实。原件继续引用原位置。

## 首页、目录与关于我

| 页面 | 完整顺序 | 桌面与手机安排 |
| --- | --- | --- |
| 首页 | 姓名／方向 → 主张与简介 → 代表项目 → 面膜、防晒、洁面 → 简短经历 → 联系 | 精华油、酷狗桌面两列且入口格式相同，手机依次单列；三个互补项目保持完整标题、问题、入口，不用悬停显示文案 |
| 作品目录 | 精华油 → 酷狗 → 面膜 → 防晒 → 洁面 | 五个紧凑条目，问题与本人工作直接可见；复用首页摘要，无需再写一套内容，不增加筛选或搜索 |
| 关于我 | 工作主线 → 工作方式 → 四段经历 → 教育、语言与工具 → 简历、作品与联系 | 三个工作方式与履历都保留；桌面可将日期列为窄栏，手机按时间和经历自然排列，不用仅靠时间线图表达文字 |

首页两份主要案例决定入口优先级，其他案例均有完整正文。顶栏“作品”进入目录，首页“看代表项目”只跳到首页代表项目；从外部直接进入任一案例，也能找到全部作品、简历和联系。

## 精华油

| 内容r3模块 | 页面安排 |
| --- | --- |
| 为双产品建立一条内容主线 | 开篇显示问题、个人职责、项目整体成果范围及代表作品；正文事实保持原样 |
| 项目任务与我的分工 | 任务常显；桌面分工表两列，手机按每条个人工作及协作说明上下对应 |
| 内容判断 | 三个判断常显，历史短句与分析相邻 |
| 海报 | 日间、夜间两组常显；资料信息一组放“补充查看：资料信息”，含完整线稿、成品与分析；三页原PDF在章节末尾 |
| 公众号 | 三个片段及逐图说明常显；25页全文直接文件入口 |
| 朋友圈 | 三张作品、任务分组及图注常显 |
| 四类视频脚本 | 四条标题、各自说明与播放器均保留；桌面两列卡片，手机单列；每条有独立文件入口，逐段分析另附 |
| 销售沟通 | 后期重建身份和结构例始终可见；全文另附，不与历史原稿混排 |
| 项目结果与贡献 | 整体GMV及范围、个人贡献与历史作品说明常显；结尾进入酷狗、其他项目或简历 |

正文中海报的结构分析与对应图组保持相邻；资料组收起时，摘要明确写出它是什么、包含几组，不以空白“更多”隐藏去向。

## 原有路由与章节

| 现有入口 | 后续实现应保留的对应关系 |
| --- | --- |
| 首页、作品、关于 | 继续兼容现有首页、作品目录、关于我；原联系入口仍定位邮件联系 |
| 五个项目 | 油、酷狗、防晒、面膜、洁面的旧分享链接继续进入对应完整案例；洁面现有路由ID为clean，内容文件名为cleanser |
| 旧章节 | 概览、策略、海报、公众号、朋友圈、话术、详情、直播、视频、成果等现有章节，按实际来源ID映射到r3对应模块；内容顺序变化不应让旧链接落空 |
| 具体海报 | 继续按各项目现有组ID定位；目标位于补充区时，先展开再定位 |
| 历史总线稿入口 | 原先跳到防晒海报章节的兼容行为保留，不重定向到无关作品 |

本表是展示安排；具体哈希值与滚动行为在HTML阶段按原路由代码核对。直接定位后，章节标题与当前焦点应可见；浏览器返回恢复列表或原阅读位置，不能把原版每次回页顶的行为当作已完成的恢复能力。
