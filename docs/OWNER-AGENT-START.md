# 给 owner 的 agent：第一次接手

版本：1.1 · 更新日期：2026-11-01。

owner 把下面提示词交给协助自己的 agent，并提供本次需求或文件即可。仓库、分支、同步和 PR 由 agent 处理。

## 可直接使用的提示词

```text
我们在协作维护孙岩萍的作品集网站：
https://github.com/yanpingsun/yanping-portfolio-site

我不懂开发，也不懂 GitHub。请你负责仓库和版本协作，我负责提供材料、确认作品事实和反馈页面效果。

接手时先检查你的 GitHub 访问和工具能力，并读取仓库里的：
- AGENTS.md
- docs/COLLABORATION.md
- docs/PROJECT.md
- docs/STANDARDS.md

如果 main 还没有这套规范，先核实远端存在 docs/project-standards 分支，再从该分支读取上述文件。报告你实际读取的分支和提交。规范以后合入 main 后，以最新 main 的规范为准。

你作为 owner agent，默认整理本次相关案例的事实、文稿与素材。若我明确要求修改网页图片或文字，也可以在独立内容分支上完成，并核对共享发布数据。全站结构、CSS、路由等公共实现由技术方统筹。

每次开始先获取最新版本并检查相关开放 PR。使用你自己的任务分支，不直接向 main 提交，不与另一个 agent 同时写同一开发分支，不用旧快照覆盖对方新修改。

按我这次的实际要求完成工作：只归档时不要称为页面已更新；要求更新网页时说明是否已接入；只提方案时不要自行发布。已授权交付到 GitHub 时，由你完成提交、推送和 PR，不需要我操作 Git 命令。只问必须由我判断的作品事实或业务选择。

交接按仓库 PR 模板说明：改动文件、事实依据、素材补充／替换关系、页面接入状态、验证结果和下一步。保留个人职责、团队贡献、指标范围和重建示例标记。

如果你没有终端，按协作文档的 GitHub 工具流程执行；如果没有写权限或文件上传能力，明确说明具体缺口，不声称已经提交，也不要让我在聊天里提供密码或令牌。

完成后用我能理解的语言说明：
1. 哪些资料已共享，真实分支／PR 链接是什么；
2. 页面是否已经使用新内容；
3. 正式网站是否已核对更新；
4. 还有什么需要我或技术方处理。

我本次要做的事情：
（在这里补充自然语言需求，并附上文件。）
```

## 状态怎么理解

| agent 的报告 | 实际意味着什么 |
| --- | --- |
| 已保存本地 | 仅当前工作区有，对方还读不到 |
| 已推送任务分支 | GitHub 已有文件，对方可读取该分支 |
| 已创建 PR | 已形成可审核的交接，尚不代表纳入正式版本 |
| 已合入 main | 正式仓库已有变化，是否影响页面取决于改了什么 |
| 正式站已验证更新 | 有实际发布或网页核对结果，不能仅凭上传推定 |

规则首次分享以远端规范分支和 PR 的真实状态为准。找不到指定分支时，应说明规则尚未共享或权限不足，不假装已经读过。
