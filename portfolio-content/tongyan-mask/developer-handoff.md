# 童颜面膜开发交接说明

更新日期：2026-10-27。

## 先读什么

1. `project.md`：完整项目稿，作为后续网页文案和案例结构的主要来源。
2. `content.json`：模块、职责、代表素材与状态的结构化数据，供开发读取。
3. `asset-manifest.json`：全部资料文件的相对路径、大小、SHA-256及素材类型。
4. `docs/`：各渠道详细分析、策略说明与私域重建示例。

## 建议页面结构

项目概览 → 我的职责 → 旧品升级的内容难点 → 六个卖点方向 → 各渠道分工 → 代表作品 → 交付总结。

代表作品可按公众号、朋友圈、视频、直播话术、商城详情页分组。私域重建示例放可选附录，不与历史作品混排。

本次仅交接资料，未修改当前网站页面。开发时保留仓库现有其他项目和页面改动。

## 图片与视频的使用

- `assets/moments/`：三组真实配文与配图，一一对应。编号是展示分组，不是历史发布顺序。
- `assets/wechat/`：完整公众号PDF及5张提取配图。正文与配图分工均已确认。
- `assets/detail/`：用户指定的两张完整长图。两张有重叠内容；节选展示时避免重复，并保留完整原图查看入口。
- `assets/videos/`：三条网页展示副本，保留声音和时间轴，已处理第三条通知区域。原始录屏未公开上传。
- `assets/video-stills/`：由处理后视频导出的关键帧，与视频时间对应。
- `assets/live/`：8张产品讲解、3张补充下单截图；SOP PNG及PPTX为后期整理附件。
- `assets/candidates/`：4张前期选材备选，非已确认朋友圈配文组合，默认不放主展示。

视频优先用原生`<video controls preload="metadata" playsinline>`，不要默认自动播放。为每条视频配置关键帧封面。长图用缩略预览加点击原图，避免将整张超长图压成不可读的小字。GitHub的Markdown预览不等于网站播放器，网站中可直接引用同仓库相对资源路径。
